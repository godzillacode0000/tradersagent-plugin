What runs where

    
    
      
  • • Desktop app = surface only (row, route, pane, palette, chip)
    • 
      
  • • Console = Python stdlib server + the chart page, one systemd unit
    • 
      
  • • Chart = Vela + PineTS from CDN, Binance public data
    • 
      
  • • Nothing runs in the cloud for you: no accounts, no telemetry
    • 
    

  

  

    
The fast path

    
    
      
  • • Agent → CLI/MCP → /api/chart/command → SSE push → page runs it
    • 
      
  • • Result comes back on the same round trip (inline wait)
    • 
      
  • • add indicator ~37 ms · market switch ~150 ms · screenshot ~70 ms
    • 
      
  • • Fallback: the file bridge + 2 s polling if the stream drops
    • 
    

  

  

    
Two rules that keep it sane

    
    
      
  • • One claim per command — several consoles can be alive; only one executes
    • 
      
  • • Build + viewer in every heartbeat — a stale frame is visible, not mysterious
    • 
      
  • • reload is once-per-view, so a stale frame cannot stay stale
    • 
      
  • • Theme: console theme → ChartPalette.enforce → Vela rendererConfig
    • 
    

  

  

    
Honest limits

    
    
      
  • • Pine runs through PineTS (subset): no import, no while, no for…in
    • 
      
  • • Vela's own Pine engine is a paid feature — not used here
    • 
      
  • • Needs the local service + CDN; offline = no chart
    • 
      
  • • No trading: reads, styles, draws, computes — no orders, ever
    •
