Trader's Agent · Hermes Desktop plugin

One chart, three doors, one bridge

Hermes is the brain; the chart is its controllable visual workspace. The plugin never reaches the chart directly — it frames a local console, and every caller (CLI, MCP client, chat agent) pushes through a single durable bridge that the page executes and answers.

6,670 LOC · 29 MCP tools · 14 CLI subcommands · 163 tests green

Three doors

Who can command the chart

  • trader-chart — 14 subcommands; polls for the answer
  • MCP — 29 tools, global in Hermes config, so a brand-new session already has them
  • chat.py — the desk agent, spawned via CHAT_CLI

Lifecycle

One command, end to end

  • Caller → bridge → SSE push → one view claims it → runs in the browser → result returns
  • A preflight refuses if no page checked in within 10s, so the queue is never touched
  • SSE is the fast path; a 2s poll is the fallback — a dropped stream is not a lost command

The honest edges

What it will not do

  • No orders, account or positions — read-only market data
  • No browser exit anywhere in the UI; absence is pinned by test
  • PineTS is a Pine subset — import, while, for…in are refused out loud
